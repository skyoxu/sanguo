T2阶段「最小可玩闭环」PRD文档
系统范围与目标

本项目是一款基于 Godot 4.x、使用 C# 开发的2D单机游戏，题材取自三国时期，玩法类似“大富翁”（Monopoly）。地图采用真实三国地理的“城池-州郡”结构，设计为环形单一路线（无分叉）。本文件定义T2阶段的最小可玩闭环，实现核心游戏循环和基础玩法。

范围：在该阶段，游戏包含玩家与AI对手（总人数 4–8），支持新游戏配置（地图/人数/起始资金档位/选角与AI补位）、回合制掷骰移动、落地动作（买地/收租/建造/触发事件/设施动作）、周期性收益结算、行动卡（BeforeRoll 0/1）、PVE 战斗（可快速结算）与掉落（含宝物/卡牌/金钱）、以及明确的破产出局与结算界面。时间“日/月/年/季度/年度”仅作为 UI 投影显示，不参与任何逻辑计算；季度/年度事件在本阶段已弃用，由 RoundNumber 驱动的全局事件机制替代。游戏为单机离线模式，平台限定为 Windows（Godot Mono 版本）。


目标：实现“可复现开局 → 回合循环（BeforeRoll→掷骰→移动→落地动作）→ 经济结算/全局事件/战斗（可选）→ 胜负判定 → 结算界面 → 回主菜单”的完整可玩闭环。保证同一输入（配置+random_seed+状态）可复现同一输出；所有经济数值计算仅在 Core 发生，UI 只展示事件/投影字段；事件命名遵循 ADR-0004（CloudEvents-like type）。

范围锁死与非目标（T2总则）

硬范围（本阶段必须交付）
- 可复现开局：GameStartConfig（地图/人数/资金档/间隔/选角与 AI 补位）通过 Core 校验并发布开局事件。
- 回合骨干：BeforeRoll（行动卡 0/1）→ 掷骰 → 移动 → 落点结算 → 推进回合；周期逻辑以 RoundNumber 驱动。
- 地图与内容：只读 Data 配置（地图/角色/事件/行动卡/建筑/设施/宝物/州郡），不做目录扫描。
- 经济与结算：steps 体系（0.5 步进、clamp 到 0.5x..3.0x）；经济计算只在 Core；UI 只展示事件快照（applied_multipliers）。
- PVE（止损版）：可进入场景或快速结算；AI 一律不进入战斗场景；掉落包含金钱/行动卡/宝物。
- 终局：资金 <=0 出局；仅剩 1 名未出局角色胜利；进入结算界面并返回主菜单。

非目标（本阶段明确不做）
- PVP（含战斗卡池/对战匹配/联网对战）。
- 存档系统与回放编辑器（只保留审计事件与日志取证，便于定位问题）。
- 角色成长（体力/技能树/装备/升级）与复杂战斗系统。
- 美术/动画/音效打磨与高频交互优化（以可测、可复盘、可玩闭环为优先）。
- 内容热更新与编辑器工具链（Data 仅作为只读内容输入）。

风险与止损（PM 口径）
- 数据无效：任何 Data 校验失败必须禁止开始，并产出可追溯审计信息。
- 启动失败：必须清理已创建状态并回滚到配置界面（T54 错误码与 20s 超时口径为准）。
- 确定性：所有抽样必须可复盘（rng_context 取证字段），禁止 UI 参与计算或推导。

用户故事

掷骰前进：作为玩家，我希望每回合掷骰子移动我的棋子，以随机步数在地图城池间前进，体验不可预测的行军过程。

购地收租：作为玩家，当我的棋子停在一个无人占有的城池时，我希望能够购买该城池，将其纳入我的资产；当停在他人拥有的城池时，我需要支付过路费给拥有者，体现资源争夺与经营策略。

收益结算：作为玩家，我希望按固定轮次周期自动结算我所拥有城池的收益（例如每 15 轮一次；UI 可投影为“月末”），使我的资金随着进程增长，增加经营管理的维度。

全局事件：作为玩家，我希望每轮开始前触发全局事件检查，并可能对特定区域或经济/战斗产生影响，为游戏增加变化与策略性（同输入可复现）。

终局与结算：作为玩家，我希望当资金降为 0（或以下）时出局；当只剩 1 个未出局角色时判定胜利，并进入结算界面查看结果与统计快照。

轮流对抗：作为玩家，我希望能和AI对手轮流行动，看着AI也掷骰、走格、买地或付费，使游戏具有竞争性和挑战性。

关键硬约束（本阶段必须满足）：
- 总人数 players_count 固定为 4–8（含玩家），玩家只控制 1 个角色；其余席位由 AI 补位且不可重复角色。
- 地图为无分叉的循环轨道（track）；格子语义最小集合：city / facility / event / empty。
- 确定性：同一输入（GameStartConfig + random_seed + 状态）必须可复现同一输出；随机抽样必须产出可复盘取证字段（rng_context 等）。
- 经济：倍率使用 steps 体系（0.5 步进、clamp 到 0.5x..3.0x），仅 Core 计算；UI 只展示事件 payload（含 applied_multipliers）。

验收条款写法（便于后续测试落地）：
- 每条验收必须能落到 ACC:Txx.n，并能映射到一个或多个可执行测试文件路径（Test-Refs）。
- 验收关注【输入/动作/输出/失败提示】，避免使用模糊词（例如: 正常/合理/大概）。

任务骨架（T50–T60）

T50 Spine: GameStartConfig 与可复现开局输入
- 范围：定义唯一 `GameStartConfig`（map_id / players_count / starting_money_preset / global_event_interval_turns / random_seed / character_assignments），并以事件对外发布。
- 口径冻结：GameStartConfig 的审计快照必须使用“规范化 JSON”（UTF-8、LF、键排序、稳定字段名；不依赖对象枚举顺序），以保证 diff/复盘稳定。
- 口径冻结：所有域事件必须携带 `CorrelationId`/`CausationId`（ADR-0024）；它们仅用于链路追踪，不得影响任何玩法计算与确定性结果。
- 口径冻结：Data 校验失败属于 `data_invalid`，必须审计记录（至少包含 path/sha256/version/reason），并阻止开始。
- 口径冻结：i18n 统一使用 `message_key + params`；params 必须是扁平键值（仅 string/int/decimal/bool），禁止嵌套对象/数组，降低 UI 解析复杂度。
- 非目标：不做存档；不做 UI 美术与动画；不做角色成长。
- 验收：
  - ACC:T50.1 `GameStartConfig` 字段/范围/唯一性校验通过。
  - ACC:T50.2 地图列表仅从 `res://Data/maps/_index.json` 加载，不扫描目录。
  - ACC:T50.3 新游戏完成后发布 `core.sanguo.game.started`（含 `game_start_config` 与 `random_seed`）。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task50GameStartConfigTests.cs`
  - `Tests.Godot/tests/UI/test_task50_new_game_setup_flow.gd`

T51 Spine: 倍率合成规则与 applied_multipliers 事件快照
- 范围：统一 steps 合成（0.5 步进，稳定可复现）：
  - `base_steps = 2`（=1.0）
  - 对每个经济点：`effective_steps = clamp(base_steps + sum(step_delta), 1, 6)`，`effective_multiplier = effective_steps * 0.5`
  - 金额：`amount = floor(base_amount * effective_multiplier)`（UI 不参与计算）
  - 并把“本次实际使用的 effective_steps / sources_step_deltas”写入相关经济事件 payload（`applied_multipliers` / applied_steps 概念上等价）。
- 非目标：不引入复杂浮点档位（仅 0.5 步进）；不支持 UI 侧推导。
- 验收：
  - ACC:T51.1 任意组合输入下 `effective` 必须 clamp 到 [0.5, 3.0]，且只允许 0.5 步进。
  - ACC:T51.2 经济相关域事件 payload 必含 `applied_multipliers`（只读快照）。
  - ACC:T51.3 UI 事件日志仅展示事件里的倍率快照，不参与计算。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task51MultiplierCompositionTests.cs`
  - `Game.Core.Tests/Tasks/Task51AppliedMultipliersPayloadTests.cs`
  - `Tests.Godot/tests/UI/test_hud_event_log_applied_multipliers.gd`

T52 Spine: 回合窗口锁死（BeforeRoll 行动卡 0/1）与事件触发顺序
- 范围：锁死回合阶段（至少含 BeforeRoll），止损版每回合最多使用 1 张行动卡（0/1）；并锁死“全局事件检查/抽卡/行动卡/掷骰/移动/落点效果”的顺序。
- 非目标：不做多卡连锁；不做 PVP。
- 回合顺序（本阶段锁死，便于测试与复盘）：
  1. PreTurn：若 `RoundNumber` 达到 `global_event_interval_turns` 周期边界，则触发 1 次“全局随机事件”（source=global），发布 `core.sanguo.random_event.applied`。
  2. `core.sanguo.game.turn.started`：进入该行动者回合。
  3. Draw：按配置发 N 张行动卡（本阶段默认 0）；抽到的卡强制入手牌；若超过上限则弹弃牌界面，不弃牌无法继续（AI 走同规则，仅决策自动化）。
  4. BeforeRoll：玩家可使用 0/1 张行动卡；使用后发布 `core.sanguo.action_card.played`，并影响本回合 `AppliedMultipliers`。
  5. Roll&Move：掷骰并移动（可逐格动画；逻辑不依赖动画），发布 `core.sanguo.dice.rolled` / `core.sanguo.board.token.moved`。
  6. ResolveLanding：结算落点（city/pass/event/empty）并结束该行动者回合。
  7. `core.sanguo.game.turn.advanced`：推进到下一位行动者；当推进造成一轮结束时 `RoundNumber+1`。
- 验收：
  - ACC:T52.1 BeforeRoll 窗口每回合只允许 0/1 张行动卡。
  - ACC:T52.2 同一回合内“事件格触发 + 每N回合全局事件”的顺序固定且可测。
  - ACC:T52.3 任何顺序相关事件都可从事件日志中复盘。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task52TurnWindowOrderingTests.cs`

T53 模块: 地图配置（多文件）与 Tile 语义
- 范围：多文件地图配置：索引 `_index.json` + 单图 `<map_id>.json`；track 为任意循环轨道（格子数以 `track.length` 为准，例如 45）；Tile 最小集合：city / facility / event / empty。
  - 口径冻结：资源路径必须做规范化与绕过拦截：拒绝 `..`、拒绝 percent-encoding 绕过（如 `%2e%2e`），并拒绝任何非 `res://`/`user://` scheme（ADR-0019）。
  - 口径冻结：facility action 参数必须强类型且可校验（例如 teleport 只允许 `target_mode=tile_id|random`；mode=tile_id 时必须给出 `target_tile_id`）。
  - 口径冻结：actions.params 为强类型 JSON 对象；按 action_kind 设字段白名单（未知字段=数据无效，禁止开始），避免内容侧随意加字段导致 Core 逻辑分叉与测试爆炸。
  - 口径冻结：地图/设施/事件/建筑配置必须包含 `schema_version`；不等于当前支持版本则拒绝加载（不做迁移）。
  - 口径冻结：Core 只识别 `tile_kind = city | facility | event | empty`；当 `tile_kind=facility` 时必须给出 `facility_kind`（荒野/商店/战场/监狱/医院/职业所/传送点等）。
  - 口径冻结：`tile_id` 仅要求 map 内唯一；跨地图允许重复。
  - 口径冻结：`layout:{x,y}` 必须在 `[0,1]`（归一化坐标、原点左上）；越界视为数据无效，禁止开始（硬失败）。
  - 口径冻结：任何资源路径（地图预览、action 图标等）必须位于 `res://Assets/...` 子树内，且扩展名白名单（.png/.webp/.svg）+ 大小上限（1MB）。
  - 口径冻结：`action_id` 在同一 tile 内唯一；事件/日志引用使用 `(map_id, tile_id, action_id)` 组合，避免重排导致语义漂移。
  - 坐标：tile 带 `layout:{x,y}` 归一化坐标，原点左上角(0,0)，UI 负责缩放/自适应（不做旋转）。
  - facility：允许 `facility_id`（引用 `res://Data/facilities.json`），用于荒野/商店/战场/监狱/医院/职业所/传送点。
  - actions：稳定 `action_id` + `icon_res_path`，city 必含 buy_land（可选 build），event 必含 trigger_event，facility/empty 按配置。
  - 传送点（teleporter）止损语义：
    - 不允许传送到自身 tile；允许传送到出局角色占用格；不需要“路径经过格”的动画/事件。
    - 传送落点会执行一次落点结算（触发落地事件/付费/购买/设施 actions 等）后结束回合；落点结算只允许执行一次，禁止在该次落点结算中再次触发战斗或 teleport（防连锁）。
- 验收：
  - ACC:T53.1 `_index.json` 可列出可用地图（id/name/path）。
  - ACC:T53.2 `<map_id>.json` 中每个 tile 有确定的 type 与 name；UI 能显示 name。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task53MapConfigTests.cs`

T54 模块: 新游戏配置界面（地图/人数/资金档/全局事件间隔/选角）
- 范围：新游戏界面作为唯一开局入口：选择 map、players_count(4-8)、starting_money_preset(5000/10000/20000)、global_event_interval_turns(5/10/20)、玩家角色；剩余席位由 AI 随机补位且不可重复。
- 口径冻结：启动失败的 error_code 枚举固定为：`data_invalid` / `config_invalid` / `runtime_failed` / `timeout` / `security_denied`；同类原因必须复用同一 code，避免 UI/测试分裂。
- 口径冻结：启动失败回滚必须包含地图/角色/人数/资金档/间隔（全部回滚到默认），并重生 random_seed（你已确认）。
- 口径冻结：默认选中“第一张地图 + 第一个角色”，未选地图/未选角色时禁用开始按钮（但默认会自动选中）。
- 口径冻结：启动超时默认 20 秒（可由环境变量覆盖）；超时/失败必须清理已创建的 GameLoop/状态并回滚到配置界面。
  - 约束：开始游戏前必须满足 `available_character_count >= players_count`（角色不可重复），否则 UI 必须阻止开始。
  - 启动失败策略：失败弹窗（error_code+message）后自动回滚默认地图/默认角色/默认人数/默认资金档，并重生 random_seed（避免卡死在不可开局组合）。
- 验收：
  - ACC:T54.1 UI 可完成上述配置并进入游戏。
  - ACC:T54.2 AI 补位：角色全局唯一，不与玩家重复。
- Test-Refs（占位）：
  - `Tests.Godot/tests/UI/test_task54_new_game_menu_flow.gd`

T55 模块: 角色配置（≥8角色）与战斗基线
- 范围：角色属于配置（只读）；包含经济系数与战斗基线：BuyPriceMultiplier / TollMultiplier / MonthSettlementMultiplier / CombatRating。
- 口径冻结：角色配置必须包含 `schema_version`；不等于当前支持版本则拒绝加载（不做迁移）。
- 口径冻结：角色头像资源路径必须位于 `res://Assets/...`，扩展名白名单（.png/.webp/.svg），大小上限 1MB；越界/非法则禁止开始。
- 验收：
  - ACC:T55.1 角色配置可加载且 ≥8 角色可展示。
  - ACC:T55.2 `CombatRating` 为静态战斗强度基线（整数）；PVE 用它与 `encounter_target` 对比判定胜负；relic/事件若影响战斗，则影响“本次战斗有效 combat_rating 快照”，并写入 `core.sanguo.combat.ended` 的 result（用于复盘）。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task55CharacterConfigTests.cs`
  - `Tests.Godot/tests/UI/test_task55_character_select_ui.gd`

T56 模块: 随机事件池（事件格 + 每N回合全局事件）
- 范围：事件格触发 + 每 N 回合全局事件统一进入 RandomEventPool；止损版事件 effectKind 仅允许 `moneyDelta` 或 `economyStepDelta`（steps 为整型步进，1=+0.5；最终仍按 T51 口径 clamp）。
- 冷却：scope=player_id；对某玩家生效后，在接下来 N 个该玩家行动次数内不再对该玩家生效（计数口径：该玩家每次成为 ActivePlayerId 时 player_action_count +1）；若对当前玩家“可选事件集合”因冷却为空，则忽略冷却规则回退为全量事件均匀抽样（避免死锁）。
- 验收：
  - ACC:T56.1 事件格触发能从池中取出事件并应用。
  - ACC:T56.2 每 N 回合全局事件触发稳定可复现（由 seed 驱动）。
- Test-Refs（占位）：
  - `Game.Core.Tests/Tasks/Task56RandomEventPoolTests.cs`

T57 模块: 行动卡模块（开局发牌 + BeforeRoll 0/1 + 强制弃牌）
- 范围：行动卡池（配置只读）；开局固定发 3 张；每轮可配置发 N 张（本阶段默认 0）；仅在 BeforeRoll 窗口可用；止损版每回合最多 1 张；效果仅 `economyStepDelta`（steps 为整型步进，1=+0.5）。
  - 抽到的卡强制入手牌（无“放弃抽卡”选项）。
  - 手牌上限固定为 5：若抽卡导致超上限，则必须进入弃牌界面并丢弃至 ≤5，否则回合无法继续（AI 同规则，仅弃牌决策自动化）。
- 验收：
  - ACC:T57.1 行动卡只允许 BeforeRoll 使用，且 0/1。
  - ACC:T57.2 使用行动卡后发布 `core.sanguo.action_card.played`，并影响本回合经济倍率快照。
