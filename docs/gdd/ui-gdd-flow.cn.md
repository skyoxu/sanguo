# 三国第 7 章 UI 接线看板

## 1. 设计目标

### 1.1 体验支柱
- 稳定入口：启动、继续与运行时进入路径都必须明确且可恢复。
- 可读循环：阶段、压力、资源、HP、提示与结果必须仅凭 UI 就能理解。
- 可解释系统：配置、治理、存档、迁移与审计状态必须有可见归属，而不是隐藏在日志中。
- 确定性恢复：失败、非法操作、持久化与回退状态必须可复现且可见。

### 1.2 目标用途
- 为当前所有已完成任务能力提供一个受治理的统一规划界面。
- 让第 7 章在仅做润色之前，先聚焦面向玩家或面向运营的界面归属。

## 2. 核心玩家循环

1. 从稳定的入口界面启动或继续。
2. 进入运行时循环，并可读地看到阶段、时序、压力与生存状态。
3. 通过受治理的界面与战斗、经济、成长和元系统交互。
4. 对胜负、存档/读档、配置治理和迁移结果提供可见反馈。

## 6. 屏幕与界面要求

### 入口与启动
- 受众：面向玩家。
- 空状态：Save 头信息在存档/读档后无需检查瞬时 UI 状态，仍足以解释并复现对局上下文。
- 失败状态：战役运行模式隔离必须被明确定义并用可观察边界验证：进入战役运行模式时只应用预期的隔离行为，非战役路径不得因这次拆分而被隔离。
- 完成结果：UI 日期显示应清晰表达年/月/日；当游戏日期连续变化多次时，每一次日期变化都能在可观察层面反映为日期文本的对应更新，并且日期文本始终反映最新游戏日期（不出现回退为旧值或停滞不更新等可观察异常）。

### 核心循环状态与结果
- 受众：面向玩家。
- 空状态：集成闭环必须显式验证草案的确定性行为：在相同输入条件和 种子 下，任务 119 与 120 的 RewardDraftEngine 证据必须产出可重复的草案结果；缺少确定性证据时，任务 78 保持开启。
- 失败状态：该任务的最小“重要事件”集合为：`core.sanguo.dice.rolled` + `core.sanguo.city.bought`；日志在隐藏/显示之间保留历史；无效/格式错误的 JSON 载荷不会导致崩溃，也不会追加误导性的日志项。
- 完成结果：包含城池占有状态显示的 UI 场景与控件在无头冒烟测试中可被实例化并加载完成（无崩溃、无报错），且界面上存在用于呈现“占有状态”的可见元素。

### 战斗压力与交互
- 受众：面向玩家。
- 空状态：GdUnit4：提供并运行一个场景/UI 测试，验证 Tile 名称可见，并且在缺少 i18n 时回退到 nameKey。
- 失败状态：xUnit：`tiles[]` 必须非空（`length >= 1`），以确保 `tiles[0]` 存在；否则地图定义无效。
- 完成结果：xUnit：`tiles[]` 必须非空（`length >= 1`），以确保 `tiles[0]` 存在；否则地图定义无效。

### 经济、建造与成长
- 受众：面向玩家。
- 空状态：在获取到所属运行时的数据之前，不显示任何活动经济状态
- 失败状态：回合循环正确处理出局者：已出局 NPC 会从后续轮转中跳过且不再行动；真人玩家一旦出局，回合循环立即停止并触发游戏结束；游戏结束后进一步调用 AdvanceTurn/AdvanceTurnAsync 必须被拒绝（抛出 InvalidOperationException）且不得推进日期/轮转行动者/发布新事件；NPC 出局后其状态锁定，且其已占领城池被释放为无人占领。
- 完成结果：玩家可以从 UI 状态中读取确定性的资源与成长结果。

### 元系统与平台
- 受众：面向玩家或混合。
- 空状态：在 游戏流程 流程中，玩家于 TurnPhase.BeforeRoll 阶段每回合最多只能成功打出 1 张行动卡；同回合第二次尝试必须被拒绝且不产生任何 multiplier_step_delta/效果输出，并与 后端视图的窗口锁死语义一致。
- 失败状态：在回合/循环结算时，若真人玩家因资金不足以支付全额过路费而出局（破产结算）：其剩余资金必须转移给收款方，玩家资金归零并标记出局；立即进入 GameOver 且后续回合推进必须被拒绝（再次调用 AdvanceTurnAsync 抛出 InvalidOperationException，且消息包含 "GameOver"）。若 NPC 因资金不足以支付全额过路费而出局：同样进行破产结算后退出本局并从后续轮转中移除（状态锁定，后续不会再成为 ActivePlayerId），其已占领城池状态变更为无人占领。
- 完成结果：开始游戏启动失败时（例如地图配置加载失败），主菜单必须恢复为可交互状态并显示可观测错误提示（例如 StatusLabel 显示“Start failed”），避免出现“菜单消失但游戏未开始”的死路。

### 配置治理与审计
- 受众：面向运营或混合。
- 空状态：在运行时数据可用之前，不显示任何活动中的对局状态。
- 失败状态：`quality_gates.py` 在统一门禁流程中读取上述两份报告并应用 Phase-13 约定的阈值规则输出 PASS/FAIL（示例：Dup% ≤ 2%，最大圈复杂度 ≤ 10，平均圈复杂度 ≤ 5）；当任一报告缺失/不可解析/缺少必要字段时必须判定为 FAIL，并输出可定位原因的错误信息。
- 完成结果：运营方或玩家可以从受治理界面查看配置、校验、迁移与审计状态。

- 当面向玩家的交互不合适时，允许提供面向运营的只读界面。

## 7. 界面级契约

### 7.1 MainMenu 与启动流程
- 覆盖切片：入口与启动。
- 必须显示：开始、继续、重试引导以及平台启动校验状态。
- 不得隐藏：不得把启动失败、继续门禁拒绝或导出/运行时启动问题仅藏在日志里。
- 校验重点：启动路径、继续门禁、重试流程与启动校验证据。

### 7.2 运行时 HUD 与结果界面
- 覆盖切片：核心循环状态与结果。
- 必须显示：阶段、计时器、HP、提示、奖励入口、非法操作提示、速度状态与终局结果。
- 不得隐藏：不得隐藏任何在没有可见 HUD 或结果反馈时发生的终局或提示状态切换。
- 校验重点：HUD 状态变化、提示、奖励可见性与胜负切换。

### 7.3 战斗压力与交互界面
- 覆盖切片：战斗压力与交互。
- 必须显示：压力、生成节奏、目标选择、寻路回退、战斗结算与镜头交互状态。
- 不得隐藏：不得隐藏仅出现在日志或追踪中的战斗压力或目标选择变化。
- 校验重点：战斗反馈、压力可见性、寻路回退证据与镜头交互冒烟检查。

### 7.4 经济与成长面板
- 覆盖切片：经济、建造与成长。
- 必须显示：资源总量、建造放置状态、队列状态、升级/修理状态、科技状态与成长结果。
- 不得隐藏：不得隐藏没有受治理反馈的非法消耗、建造或成长状态切换。
- 校验重点：资源确定性、建造校验、队列行为与成长界面证据。

### 7.5 存档、设置与元系统界面
- 覆盖切片：元系统与平台。
- 必须显示：存档/读档状态、云端状态、本地化状态、音频状态、性能状态与平台/运行时状态。
- 不得隐藏：不得隐藏只能在底层日志中看到的持久化或设置失败。
- 校验重点：存档/读档流程、云同步、本地化/音频控制与平台状态可见性。

### 7.6 配置审计与迁移界面
- 覆盖切片：配置治理与审计。
- 必须显示：当前配置、模式状态、回退状态、迁移状态、配置审计元数据与报告元数据。
- 不得隐藏：不得隐藏没有出现在受治理只读界面上的校验、回退或迁移结果。
- 校验重点：配置校验、治理、迁移与审计元数据证据。
